# Review claims separately

A finding needs the scene/inference ID, observation, learner consequence, severity, suggested discriminating recheck, artifact revision, and reviewer relationship. Use current/revise/unverified states with reasons. Numerical beauty or intuition scores are not evidence.

| Claim | Evidence needed |
|---|---|
| Subject correctness | Valid claims, assumptions, units, argument/proof, primary references, relevant edge checks |
| Explanatory adequacy | Learner-visible warrant for each critical bridge; missing prerequisites and wrong-rule cases |
| Whole-route coherence | Cold walkthrough: why this lesson, why these steps, how the final method answers the opening question |
| Visual/interaction usability | Rendered meaningful states at intended sizes; actual control use, labels, coupled outputs, attention burden |
| Runtime | Clean start, real navigation, persistence/reset, notebook return, failure recovery |
| Simulated learner review | Recorded uncoached task attempts with warrants; disclose existing topic knowledge and model/context |
| Human learning | Actual audience, baseline, tasks, help, observations, scoring, limits |
| Comparative learning | Matched goal/time/depth and suitable comparison design; separate preference from performance |
| Retention / delayed transfer | Actual delayed tasks; recall and new-context transfer recorded separately |

False central claims, missing requested argument, broken critical controls, hidden required prerequisites, or unreadable critical scenes block a ready artifact claim. Human efficacy can remain unverified in a clearly labeled reviewed candidate. Do not let available software tests stand in for missing teaching evidence.

## Review protocol

Give an unfamiliar reviewer only the audience, task, learner-visible artifact, and neutral criteria for the first pass. Do not supply the author's diagnosis or desired verdict. Obtain separate initial observations, then cross-critique. Record prior authorship, shared history/model, assistance, and source access. “Elite educator” is a role request, not a credential.

Hold back new assessment cases and expected reasoning from the author where feasible. A knowledgeable AI may answer correctly without learning anything: require a pointer to the visible explanation that warrants the inference, and preserve failures. After repair, repeat the affected test; also trace global coherence if the route changed. Do not repeat unchanged reviews for reassurance.

A user's rejection reopens the relevant acceptance. It need not negate valid mathematical or runtime evidence. Tie the next change to a falsifiable teaching hypothesis.

## Plain language and the 80% target

Use short active sentences, stable terms, one main idea, defined symbols, and concrete instructions. Preserve mathematical precision. ASD-STE100-inspired wording is not formal compliance.

For this user's 80% compatibility target, the denominator is all learner-facing prose sentences in slides, controls, feedback, and refreshers. Exclude equations/code, but review their labels. Mark each sentence compatible, incompatible, or unverified, with technical-name exceptions and reasons. Unknown sentences are not passes. Report compatible/total and review coverage.

Use the actual applicable standard and vocabulary/usage rules if available. Sentence-length checks alone cannot establish compliance. If the full audit is unavailable, improve the wording, report measured checks, and leave the percentage unverified.

## Behavior tests for a changed skill

Use isolated artifacts. Include an unfamiliar quantitative bridge and a nonmathematical explanation; request real learner-facing samples, not only plans. Add a brief factual answer, retrospective-only request, inaccessible video, correct-answer/wrong-reason, capped repeated failure, stale artifact, and detour return where relevant.

Record prompts, outputs, held-out criteria, observations, repairs, exact inspected skill revision, candidate model/context when available, and review provenance. Label each result as written response inspected, execution independently verified, or learner performance observed. A written scope promise does not prove the action was executed. Structural validation proves packaging; CLI tests prove specified guardrail behavior; forward tests show behavior on sampled requests. None proves durable human intuition or superiority to expert teaching.

Use evidence labels such as planned, working draft, reviewed candidate, simulated-review completed, learner-observed, or comparative-study completed. Avoid “expert-reviewed” unless the reviewer's expertise and actual review are defensible.
